## Структура hero
Hero одразу відповідає на 4 питання: хто ми / що створюємо / для кого / яку користь отримує клієнт. Приклад смислової структури зі спеки:

```text
Створюємо цифрові продукти, які допомагають бізнесу зростати

Сайти, мобільні застосунки, CRM, ERP, SaaS та AI-рішення — від ідеї й дизайну до запуску та підтримки.
```

Поруч — сильна візуальна демонстрація (interactive mockup, dashboard, mobile app, landing page fragment), не абстрактна 3D-фігура без зв'язку з послугами.

## Стандартні CTA-лейбли
- Первинний CTA: **«Обговорити проєкт»** (альтернатива — «Розпочати проєкт»)
- Вторинний CTA (hero): **«Переглянути роботи»**
- Фінальний CTA-блок сторінки (розділ фінального CTA-блоку проєктного спеку): «Обговорити проєкт» + «Отримати попередню оцінку»

## Розміщення
- Header (розділ header проєктного спеку): один основний CTA, завжди видимий, header змінює вигляд після прокручування, але лишається візуально легким і не перекриває контент.
- Hero: primary + secondary CTA поруч, primary візуально домінує (колір/вага), secondary — outline/text-style.
- Фінальний CTA-блок сторінки — окрема секція перед footer, не тільки в hero.

## Rules
- Лейбли CTA не вигадувати заново на кожній сторінці — використовувати ці стандартні варіанти для консистентності конверсійної воронки.
- Кожен CTA веде на конкретну дію (форма, `/start-project`, `/projects`) — не на "заглушку" чи скрол в нікуди.
- Нову CTA-концепцію вводить `cro-specialist`; `copywriter` лише пише текст у вже визначеній структурі.
