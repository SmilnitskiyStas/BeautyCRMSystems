## Сценарії (розділ тестування проєктного спеку)
- Відкриття головної сторінки
- Перемикання мови (`/uk` ↔ `/en`, зберігає поточну сторінку/контекст)
- Navigation (header, footer, breadcrumbs)
- Перегляд проєкту (`/projects` → `/projects/[slug]`)
- Надсилання форми (коротка і розширена) — успішний шлях
- Validation errors — форма з невалідними/відсутніми полями показує помилки, не сабмітиться
- Thank-you сторінка після успішного submit
- 404 — неіснуючий маршрут
- Mobile-меню — відкриття/закриття, навігація всередині
- Keyboard navigation — проходження ключових флоу без миші

## Rules
- Кожен e2e-тест незалежний (не покладається на стан, залишений іншим тестом).
- Форма-тести не б'ють у реальний email-провайдер — мокати provider на рівні e2e-оточення (`.env.test`), не production credentials.
- Критичні флоу (форма заявки, navigation) — обов'язкова частина CI-гейту (розділ CI/CD проєктного спеку), не тільки ручний прогін перед релізом.
- Новий публічний маршрут отримує хоча б один e2e-сценарій (load + основна дія) до merge.
