## Purpose
Будує довідкову карту keyword-кластерів — основу для контент-структури (сторінки послуг, галузеві сторінки, блог) проєкту. Карта походить зі стратегічного SEO-документа проєкту (перелік послуг/галузей + пошукового наміру клієнтів), не є буквальним списком для keyword stuffing.

## Процес побудови власного кластера
1. Взяти реальний перелік послуг/продуктів/галузей проєкту (з content-моделі чи проєктної специфікації) — кластери походять від того, що проєкт реально пропонує, не від довільного SEO-brainstorm.
2. Для кожної послуги/галузі сформувати короткий список комерційних пошукових термінів, якими реальний клієнт описав би свою задачу ("замовити X", "розробка Y") — інформаційні запити сюди не йдуть, для них є блог-таксономія (`plan-blog-taxonomy.md`).
3. Побудувати кластер окремо для кожної мови сайту (напр. uk/en) — кожна мовна версія повинна відображати природні пошукові запити реальних носіїв цієї мови, **не дослівний переклад** іншомовного кластера (пошукова поведінка й термінологія різняться між мовами).
4. Мапити кожен кластер-термін на одну конкретну існуючу чи заплановану сторінку (`/services/[slug]`, `/industries/[slug]`) — не створювати нову сторінку заради окремого терміна.
5. Тримати правило "один кластер-термін = один 'власник'-URL" — не розмивати той самий пошуковий інтент між кількома сторінками (ризик canonical/duplicate content).

## Приклад (worked example для digital product studio)

Нижче — кластер, побудований за цим процесом для проєкту типу "digital product studio" (веб-розробка, CRM/ERP, SaaS, мобільні застосунки, AI-рішення). Це ілюстрація формату й глибини кластера, а не універсальний список — під власний проєкт кластер будується заново за кроками вище.

## Rules
- Не створювати SEO-сторінку без реальної користі для відвідувача — жодних порожніх doorway pages під кожну комбінацію ключових слів, включно з термінами з прикладу вище.
- Нову сторінку в кластер додає `seo-specialist` разом з `product-designer` (контент-модель), не одноосібне рішення на льоту.
- Кластер переглядається щоразу, коли змінюється перелік послуг/галузей проєкту — терміни, що більше не мапляться на жодну сторінку, видаляються, а не залишаються "про запас".
