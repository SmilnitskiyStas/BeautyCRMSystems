## Purpose
Формує 2-3 альтернативні візуальні напрями (moodboard-рівень) + одну рекомендацію з обґрунтуванням, перед стартом фази Design foundation.

## Process
1. Зафіксувати принципи напряму з проєктного брифу візуального напряму: молодіжний, преміальний, технологічний, мінімалістичний, емоційний, сучасний, впізнаваний, візуально чистий, не схожий на готовий шаблон.
2. Підготувати 2-3 різні концепції (напр.: "темний технологічний" / "світлий преміальний мінімалізм" / "контрастний з делікатним glassmorphism") — кожна з описом типографіки, кольорової палітри, стилю зображень/mockup-ів, характеру мікроанімацій.
3. Для кожної концепції явно пройтись по забороненому списку з проєктного брифу візуального напряму і підтвердити відсутність порушень (чеклист нижче).
4. Обрати й аргументувати одну рекомендовану концепцію: чому вона краще відповідає позиціонуванню (`define-positioning-and-audience.md`) і аудиторії.
5. Передати рекомендовану концепцію `ui-ux-designer` як вхід для design tokens.

## Forbidden-Pattern Checklist (жодна концепція не повинна містити)
- [ ] Типовий шаблон агентства
- [ ] Надмірна кількість неонових ефектів
- [ ] Нескінченні анімації
- [ ] Важкі 3D-сцени без бізнес-користі
- [ ] Дрібний текст
- [ ] Низький контраст
- [ ] Стандартні стокові фото людей в офісі
- [ ] Фейкові логотипи клієнтів
- [ ] Фейкові відгуки
- [ ] Каруселі, що погано працюють на мобільних пристроях
- [ ] Автозапуск відео зі звуком
- [ ] Анімації, що блокують взаємодію
- [ ] Великі JS-бібліотеки без потреби

## Guardrails
- Не перевантажувати жодну концепцію анімаціями ("не перевантажувати сторінки анімаціями").
- Кожна концепція повинна явно визначати dark/light підхід — не залишати тему "на потім".

## Output
Датований moodboard-документ: 2-3 концепції (опис + референси/палітра/типографіка) + рекомендація з обґрунтуванням. Проходить рев'ю `project-architect` перед стартом фази Design foundation.
